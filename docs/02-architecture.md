# 02. Архитектура

## 1. Общая схема

```
┌──────────────────────── RegWatch.app (Electron) ─────────────────────────┐
│ renderer (React, русский UI)                                              │
│   Главная · Страны · Прогон · История · Настройки · Мастер первого запуска │
│                         ▲ IPC (window.rw)                                 │
│ main (Node, вся логика)                                                   │
│   Scheduler ──► Orchestrator ──► Collector (код, 0 токенов)               │
│                     │       └──► ClaudeRunner ──► `claude -p /<skill>`    │
│                     │                               (по профилю этапа)    │
│                     ├──► Checks (цитаты, полнота, числа EN/RU)            │
│                     ├──► Ledger · RunState · Archive                      │
│                     ├──► Budget (5-часовой лимит)                         │
│                     └──► Digest ──► Mailer (SMTP)                         │
└───────────────────────────────────────────────────────────────────────────┘
               │ пишет                                   │ читает
               ▼                                         ▼
     <рабочая папка>/runs, state, .claude/skills   ~/Library/Application Support/RegWatch
```

Главный принцип: **оркестратор — код**. Модель вызывается только как узкий исполнитель одного
этапа через скилл, с фиксированными правами и JSON-схемой ответа.

## 2. Стек

- Electron + electron-vite + TypeScript + React (как в `claude_asist`, без PTY и Swift).
- Зависимости только на чистом JS: `nodemailer`, `ajv` (проверка JSON-схем), `cheerio` (разбор HTML),
  `fast-xml-parser` (RSS). Без нативных модулей.
- Тесты: `node:test` (Node 22.18+ снимает типы с `.ts`), тесты рядом с модулем `*.test.ts`.
- Сборка: `electron-builder`, ad-hoc подпись, `npm run app` копирует в `/Applications`.

## 4. Конвейер прогона

```
для каждой активной страны (по порядку, по одной):
  1 COLLECT     код: каналы А, Б, В → candidates.json, snapshots/        (0 токенов)
  2 NEWS        /news-sweep (если включён) → news.json; новые наводки → кандидаты
                  только если найдены в первичном источнике кодом
  1б CLASSIFY   код: класс органа (1/2/3) по issuer, банковские слова и фрагменты текста;
                  класс 3 без банковских слов → отброшен кодом с кодом причины   (0 токенов)
  3 TRIAGE      /triage по оставшимся кандидатам → triage.json
                  код: проверка схемы, полнота (каждый кандидат имеет решение)
  3б SCREEN     /screen-act (пакеты по 5) для relevant|borderline: фрагменты текста + реквизиты
                  → screen.json: material | minor | none | unsure
                  код: схема, цитата найдена во фрагментах, полнота
  3в CONFIRM    /screen-act в режиме подтверждения (sonnet): none при классе 1–2 и все unsure;
                  сомнительное идёт дальше (SCR-03); нет текста/ошибка → «не удалось проверить» (SCR-04)
  4 ANALYZE     для каждого material и канала А: /analyze-act → acts/<id>/card.json
                  (minor — строка «Для сведения» из экрана, без разбора)
                  код: схема, HAL-02/03 (цитаты в снимке); провал → в VERIFY с пометкой
  5 VERIFY      /verify-report по стране (только карточки material и канала А) → verification.json
                  minor проверяет код: номер и дата есть в снимке
                  mismatch ключевых полей → /analyze-act с замечаниями → снова VERIFY (≤ 2 кругов)
                  returned (возвращённые из отброшенного, только с обоснованием) → SCREEN → ANALYZE → VERIFY
  6 STATUS      код: completeness → changes | no_changes | failed:<причина>
после всех стран:
  7 DIGEST      код: report.en.md по стране, digest.en.md
  8 TRANSLATE   /translate-ru (если язык ≠ en) → digest.ru.md, report.ru.md
                  код: LNG-03 сверка чисел; провал → RU не отправляется, помечается
  9 SEND        код: если есть хоть одна карточка или условие COV-06 → письмо; иначе ничего
 10 COMMIT      код: ledger обновляется ТОЛЬКО после успешной отправки (или сразу в пробном
                  режиме — не обновляется вовсе); last_success по странам
```

Страна без кандидатов после шага 1 пропускает шаги 3–5 (0 токенов).

**Правила второго круга (VER-03).** Второй круг `/analyze-act` → `/verify-report` запускается
только при `mismatch` **ключевых** полей (номер, даты, вступление, переходный период, ссылки,
значимые изменения). Не запускается: если у кандидата нет текста (`no_text` → «⚠ Не удалось
проверить», SCR-04); при `unverifiable` по неключевым полям; для `minor` (проверяет код).
Возврат отброшенного при проверке — только с обоснованием (`returned[].reason` называет связь с
банками) и только на экран, а не сразу на разбор.
Состояние каждого шага пишется в `run.json` атомарно (запись во временный файл + rename) до и
после шага, поэтому прогон продолжается с места остановки (RUN-06).

Ledger обновляется после отправки: если письмо не ушло, повторная отправка возьмёт те же карточки,
а следующий прогон не потеряет их.

## 6. Профили этапов (права, модели, лимиты)

| Этап | Скилл | Модель (Сбалансировано) | `--tools` | `--allowedTools` | Таймаут | `--max-turns` |
|---|---|---|---|---|---|---|
| NEWS | `news-sweep` | sonnet | Read, WebSearch, WebFetch | Read, WebSearch, WebFetch | 5 мин | 15 |
| TRIAGE | `triage` | sonnet | Read | Read | 5 мин | 10 |
| SCREEN | `screen-act` | sonnet (пресет «Экономно» — haiku; поле «Экран» в «Дополнительно», CFG-15) | Read | Read | 5 мин | 10 |
| CONFIRM | `screen-act` (режим подтверждения) | sonnet (не слабее) | Read | Read | 5 мин | 10 |
| ANALYZE | `analyze-act` | opus | Read, WebFetch | Read, `WebFetch(domain:<домен>)` по каждому домену страны | 10 мин | 30 |
| VERIFY | `verify-report` | opus | Read, WebFetch | Read, `WebFetch(domain:<домен>)` по каждому домену страны | 10 мин | 30 |
| TRANSLATE | `translate-ru` | sonnet | Read | Read | 5 мин | 8 |
| SRC-CHECK | `verify-sources` | sonnet | Read, WebFetch, WebSearch | Read, `WebFetch(domain:<домен>)` по доменам проверяемых источников, WebSearch | 10 мин | 30 |
| SRC-DISCOVER | `discover-sources` | sonnet | Read, WebSearch, WebFetch | Read (папка этапа и input), WebSearch, WebFetch | 10 мин | 30 |

`Read` везде ограничен: cwd процесса = папка страны (акта/этапа), правило `Read(//<абс. путь папки>/**)`
и `Read(//<input.json>)`, если input вне папки (FINDINGS «Фаза 3: правила Read»: разрешающие правила
не сужают чтение внутри cwd, поэтому изоляция — через cwd). У SRC-DISCOVER Read добавлен потому,
что вход приходит файлом. `--max-turns` = значение из таблицы + 2 на structured output.

**Модель ничего не пишет на диск.** Ответ каждого этапа — только в stdout по JSON-схеме
(`--json-schema`, поле `structured_output`); все файлы пишет код. Поэтому Write не выдаётся ни
одному этапу.

Этап SCREEN (и CONFIRM) — как TRIAGE: **только Read, без WebFetch** и без WebSearch: модель
видит лишь фрагменты текста и реквизиты, подготовленные кодом (`input.json`), и ничего не открывает
в сети. Cwd процесса = папка страны.

Для всех: `--disallowedTools Bash,Agent,Task,Write,Edit,MultiEdit,NotebookEdit`, `--permission-mode dontAsk`.

Пресеты (CFG-09): «Экономно» — haiku на TRIAGE/SCREEN/TRANSLATE/NEWS, sonnet на CONFIRM/ANALYZE/VERIFY;
«Сбалансировано» — как в таблице (SCREEN — sonnet); «Максимальная точность» — opus везде, кроме TRANSLATE (sonnet) и SCREEN (sonnet).
Модели задаются алиасами CLI (`haiku`, `sonnet`, `opus`), чтобы не устаревали.

Запасной путь, если `--json-schema` в CLI пользователя не работает (выяснить в фазе 0): модель
пишет ответ в один файл `<папка этапа>/output.json` с правилом `Write(<этот файл>)`, код проверяет
его той же схемой. Записать выбор в FINDINGS.

## 7. Запуск `claude -p`

```
<claude> -p "/<skill> <абсолютный путь к input.json>"
  --model <алиас>
  --tools <список>
  --allowedTools <правило1> <правило2> …        ← каждое правило ОТДЕЛЬНЫМ аргументом
  --disallowedTools Bash,Agent,Task,Write,Edit,MultiEdit,NotebookEdit
  --permission-mode dontAsk
  --setting-sources project --strict-mcp-config ← вместо --restricted (он выключает скиллы, FINDINGS «Фаза 0»)
  --max-turns <n>
  --output-format stream-json --verbose         ← для сторожа; итог — последнее событие result
  --json-schema '<схема>'
  [--no-session-persistence]                    ← если транскрипты выключены
cwd = <папка страны / акта / этапа>             ← изоляция чтения (FINDINGS «Фаза 3: правила Read»)
stdin = ignore
env = login shell env − CLAUDE_* − CLAUDECODE
```

- `--tools`/`--allowedTools` вариадические: промпт идёт сразу после `-p`, `--allowedTools` — последним
  флагом (иначе CLI примет следующий аргумент за правило). Код: `src/main/runner/stage-profiles.ts`.
- `execFile`/`spawn` с таймаутом этапа; сторож (PRM-08) убивает процесс без событий 3 минуты.
- `input.json` пишет код: пути к снимкам, тема, perspective, список кандидатов/карточек, домены.
  Модель не получает данных других стран.
- Код проверяет `structured_output` через ajv. Невалидно → 1 повтор с сообщением об ошибке схемы →
  `failed:schema`.
- Из события `result` берутся `usage`, `modelUsage`, `total_cost_usd` (для учёта, NFR-08).

### 7.1 Если скилл не вызывается через `/имя` в `-p`
Запасной путь: код читает `SKILL.md`, отрезает frontmatter и передаёт текст через
`--append-system-prompt`, а промпт — «Follow the skill instructions. Input: <путь>».
Выбор пути — по результату фазы 0, записать в FINDINGS.

### 7.2 Если нет `--restricted`
Код проверяет `~/.claude/settings.json` пользователя: если там широкие `allow` (например `Bash`),
этапы всё равно ограничены `--tools` (инструмента нет — нельзя вызвать). Записать в FINDINGS.

## 8. Бюджет 5-часового лимита (NFR-06)

Источник данных (выяснено в фазе 0, реализовано в фазе 8, `runner/budget.ts`):
1. **`rate_limit_event` из `stream-json` каждого процесса**: `five_hour.utilization` (0..1), `resetsAt`,
   `seven_day.utilization`/`resetsAt`. `claude-runner` разбирает событие в `RateLimitInfo` (`StageResult.rateLimit`),
   обёртка `observingRunStage` после **каждого** процесса передаёт его в бюджет, бюджет пишет
   `<рабочая папка>/state/rate_limit.json` (атомарно, с отметкой времени, `04` §9). Файл переживает перезапуск.
2. Статус-строка: короткий интерактивный зонд не используем (PTY запрещён) — пропущено.
3. **Обязательный запасной путь**: ошибка лимита в ответе `claude -p` → время сброса из события (или ждать
   30 мин) → пауза → продолжение с того же этапа (оркестратор). Сброс дальше 6 ч — недельное окно, см. ниже.

Решение перед каждым процессом модели (`budget.beforeProcess`, вызывают и оркестратор перед шагом, и
исполнители перед каждым пакетом/процессом; в исполнителе сигнал превращается в провал шага `budgetGate`,
чтобы расход сделанных пакетов попал в учёт):
- **Порог — абсолютная доля 5-часового окна.** Окно общее с обычной работой пользователя в Claude, поэтому
  «Не тратить больше X %» означает «не начинать процесс, когда окно уже заполнено на X %», а не «прогон
  потратил X %». Окно ≥ X % и данные свежие (моложе 5 ч, `resetsAt` впереди) → `PauseSignal` до
  `resetsAt + 30 с` → `paused_until` в `run.json`, состояние сохранено. Порог 100 % — бюджет не
  останавливает, пауза только по ошибке лимита от CLI.
- **Данных нет** (самый первый процесс) или они устарели → процесс идёт. Дешёвой пробы нет: после первого
  процесса данные появляются; перерасход ограничен одним процессом.
- **Недельное окно ≥ 98 %** (или ошибка лимита со сбросом дальше 6 ч) → **не пауза**, а `failed:limit` у
  страны с понятной причиной («Недельный лимит Claude почти исчерпан…»). Ждать сброса недели — это дни:
  незавершённый прогон блокировал бы все расписания и письмо с уже найденным. Прогон идёт дальше (остальные
  страны получают тот же итог без расхода), завершается и шлёт письмо; не проверенные страны проверит
  следующий прогон после сброса — их окно поиска считается от последней успешной проверки, пробела нет.
- Перевод письма (`createTranslator`) подчиняется тому же бюджету: на паузе перевод не получен → русское
  письмо с английскими фрагментами и пометкой «Перевод неполный» (как при ошибке лимита).

Автопродолжение (`src/main/auto-resume.ts`, `index.ts`): пауза → уведомление macOS «Проверка на паузе до
ЧЧ:ММ — лимит» и пояснение в окне → таймер до `paused_until + 5 с` шагами ≤ 1 мин по настенным часам
(таймеры Node на macOS во сне стоят) и пересчёт на `powerMonitor 'resume'` → `resumeUnfinished` (сама не
стартует дважды: общий промис + `orchestrator.running`) → уведомление «Проверка продолжена». После
перезапуска приложения срок читается из `run.json` при старте; запасной путь — тик планировщика раз в 30 с
(незавершённый прогон продолжается раньше новых, не чаще раза в 5 мин).

Оценка до прогона: стоимость этапов по прошлым прогонам (медиана на этап × число кандидатов),
веса токенов — как `limit-estimate.ts` в `claude_asist`. Если оценка превышает остаток до порога —
прогон всё равно идёт, но с паузами; пользователь видит «Отчёт придёт позже, примерно в ЧЧ:ММ».

## 9. Расписание и сон Mac

- Расписаний несколько (`settings.schedules`, до 9, SCH-01): у каждого дни, время и страны.
  `scheduler.ts` — чистые функции `nextRunTimes`, `dueRuns`, `resolveCountries`, `planQueue`,
  `rebaseline` и обвязка `createScheduler` (таймер раз в 30 с, при старте приложения и на
  `powerMonitor.on('resume')`).
- Состояние — `<рабочая папка>/state/schedule_fired.json` (атомарная запись, `04` §9): по каждому
  расписанию момент последнего срабатывания. Расписание «пора», если последнее наступившее его время
  позже этой отметки: вовремя (до 5 мин) — всегда, позже — только при «Если компьютер был выключен —
  проверить» и не старше 7 дней (RUN-03, один догон за любое число пропусков). Новое/изменённое время
  получает отметку «сейчас» — прошедшее не догоняется. Местное время: `new Date(г, м, д, ч, мин)`
  на каждый календарный день — переход часов без пропуска и дубля (SCH-05).
- Сработавшие расписания — очередь по порядку списка; прогон один за раз (RUN-07,
  `runController.start('scheduled', { countries })` с гейтом почты и проверкой `claude`); страна,
  уже взятая прогоном этой пачки, повторно не берётся. Отметка пишется только после реального старта
  (или если запускать нечего). Пока есть незавершённый прогон, новые не начинаются (RUN-06).
  Отказ — пояснение в окне «Прогон», повтор через 5 мин.
- `app.setLoginItemSettings({ openAtLogin })` (RUN-04) — при каждом старте приложения по
  `settings.launchAtLogin` и при смене флажка/сбросе раздела (только в установленном приложении,
  `app.isPackaged`); приложение живёт в трее (крестик прячет окно).
- `powerSaveBlocker.start('prevent-app-suspension')` на время прогона (RUN-05). Во время паузы по лимиту
  сон разрешён (пауза до 5 ч); короткую паузу ≤ 30 мин Mac пережидает без сна. После пробуждения таймер
  продолжения пересчитывается (§8).
- Незавершённый прогон в `run.json` при старте → продолжить; на паузе — взвести таймер до `paused_until` (RUN-06).

## 11. Письмо

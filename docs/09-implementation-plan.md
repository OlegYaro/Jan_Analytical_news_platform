# 09. План реализации

Идти строго по фазам. В конце каждой фазы: `npm run typecheck && npm test` зелёные, критерии фазы
выполнены, `docs/TRACEABILITY.md` обновлён, короткий итог фазы пользователю (что сделано, что
заблокировано и почему). Не переходить к следующей фазе с красными тестами.

## Фаза 0. Разведка окружения (до кода)

1. Прочитать все документы. Создать `docs/TRACEABILITY.md`: таблица всех ID из `01-requirements.md`
   и `07-test-plan.md` со статусом `todo`.
2. `claude --version`, `claude --help` → записать в `docs/FINDINGS.md`, какие флаги есть:
   `--json-schema`, `--tools`, `--allowedTools`, `--disallowedTools`, `--permission-mode dontAsk`,
   `--restricted`, `--max-turns`, `--output-format stream-json`, `--no-session-persistence`,
   `--append-system-prompt`.
3. Эксперименты (во временной папке с `.claude/skills/ping/SKILL.md`), результаты в FINDINGS:
   - a) `claude -p "/ping" …` — вызывается ли проектный скилл в `-p`; с `--restricted` и без.
   - b) `--json-schema` с маленькой схемой → есть ли `structured_output`.
   - c) `--permission-mode dontAsk` + запрещённый Bash → отказ без зависания, время до выхода.
   - d) `WebFetch(domain:lex.uz)` разрешает lex.uz и отклоняет другой домен.
   - e) Ждёт ли `-p` диалога доверия в новой папке.
   - f) Есть ли в `stream-json` сведения о лимите (`rate_limit`, `five_hour` и т.п.); как выглядит
     ошибка исчерпания лимита (текст, код выхода, время сброса).
   Эксперименты расходуют лимит — держать их минимальными (модель `haiku`).
4. По результатам выбрать основной или запасной путь (`02-architecture.md` §6, §7.1, §7.2, §8).
   Если в среде разработки нет `claude` или сети — подготовить скрипт `scripts/phase0.mjs`,
   который делает всё это на Mac пользователя и пишет FINDINGS; попросить пользователя запустить.

**Готово, когда:** FINDINGS содержит ответ на каждый пункт 3a–3f, выбранные пути записаны.

## Фаза 1. Каркас и установка

Electron + electron-vite + React + TS; `src/shared/api.ts`, preload; трей; single-instance;
`settings/` с версией схемы и миграцией; `secrets.ts`; `env.ts` (+тест); `doctor.ts` и
`npm run doctor`; `npm run app` (в т.ч. фолбэк на `~/Applications`); `workspace.ts` (рабочая папка,
копирование `skills/` → `.claude/skills/`, `.claude/settings.json`, `golden/`, `README.txt`).
Требования: CFG-01/02/11/13, INS-01/02/03/06, NFR-09/10/11/12, SKL-01/05, PRM-09.
**Готово, когда:** `npm install && npm run app` на чистой машине без Xcode открывает окно; doctor
показывает таблицу; рабочая папка создаётся.

## Фаза 2. Страны, источники, UI настроек

Экраны «Страны», карточка страны, формы источников и актов, seed из `08`. Разделы «Настройки»
6.1–6.6 полностью, мастер первого запуска (шаг «Почта» — полноценные поля и обязательный гейт: без
проверенной почты мастер не завершить; тестовое письмо реально отправляется с фазы 7, до неё гейт
проверяется заглушкой отправителя; шаг проверки источников — заглушка до фазы 6). Требования: CTY-*, CFG-03..10, CFG-14, CFG-12, LNG-04, NFR-14, NFR-18, INS-04 (частично).
**Готово, когда:** гейт почты (CFG-14) работает: без «проверенной почты» кнопки запуска и расписание заблокированы (`mail-gate.test.ts`); все поля из `05` есть и сохраняются; страну/источник можно добавить, изменить,
выключить, удалить.

## Фаза 3. Ядро прогона

`schemas/*.json` + типы; `stage-profiles.ts` (+тест аргументов); `claude-runner.ts` (spawn,
stream-json, сторож, таймаут, повтор, ajv, учёт usage); `run-state.ts` (+тест);
`orchestrator.ts` с конвейером из `02` §4 (этапы модели пока с заглушкой-раннером для тестов);
`ledger.ts` (+тест); `archive.ts`; экран «Прогон». Требования: RUN-02/06/07/08, PRM-*, COV-01..03,
TRI-04/05, ARC-01/02, NFR-04/05/13/15/17 (NFR-17 — дальше в каждой фазе).
**Готово, когда:** прогон с заглушками проходит все страны, переживает убийство процесса и
продолжается; тесты T-12, T-13, T-15, T-18 на заглушках зелёные.

## Фаза 4. Сбор (этап 1)

`ONDATE`), `snapshot.ts`, `collector.ts`, `anomaly.ts` (+тест), `source-health.json`.
Требования: COL-*, COV-04/05, RUN-09, SRC-08.
**Готово, когда:** сбор по UZ за 01.07–17.11.2026 возвращает кандидатов, среди которых 24/2 (3254-2)

страницах + пометка «проверить на Mac».

## Фаза 5. Скиллы и проверки

**Готово, когда:** T-1, T-2, T-6, T-14, T-16 пройдены (T-1/T-2 — на реальном Claude Code).

## Фаза 6. Проверка источников

## Фаза 11. Финальный аудит

1. Пройти TRACEABILITY построчно: у каждого ID — где реализовано и чем проверено.
2. Перечитать `01-requirements.md` и сверить с приложением вручную (каждое поле, каждая кнопка).
3. Замерить длительность полного прогона (NFR-16).
4. Прогнать все тесты T-1…T-20 или отметить `blocked` с инструкцией для пользователя.
5. Итоговый отчёт пользователю: что готово, что требует его действий (пароль почты, прогон на Mac,
   9-я страна), известные ограничения.

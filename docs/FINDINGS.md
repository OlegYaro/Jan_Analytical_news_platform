|---|---|---|
| **SMTP из приложения (выбран)**: пароль приложения почтового сервиса, отправляет код приложения (nodemailer) | Работает без участия модели и без лимита Claude; письмо уходит даже если лимит исчерпан; пароль в Связке ключей; предсказуемо, тестируется; повторы и очередь (DLV-06) | Нужно один раз создать «пароль приложения» (инструкция-ссылка в окне) |

Решение: SMTP из приложения. Пароль приложения нужен именно затем, чтобы отправка шла из самого приложения без участия модели. Почта обязательна: CFG-14, T-21.

#### Почта: шифрование и порты (по коду `src/main/mail/smtp.ts`, `src/main/settings/presets.ts`, тесты `smtp.test.ts`)
Режимы: **SSL (465)**: соединение шифруется сразу, с первого байта. **STARTTLS (587)**: соединение открывается обычным, затем по команде STARTTLS переходит на шифрование; с `requireTLS` письмо без шифрования не уйдёт (если сервер не перешёл на TLS, отправка прерывается).

| Сервис | Сервер:порт | Режим | Статус |
|---|---|---|---|
| Gmail | `smtp.gmail.com:465` | SSL | пресет |
| Outlook | `smtp-mail.outlook.com:587` | STARTTLS | пресет есть, **с реальным сервером не проверялся** (решение пользователя, замечание №12: у Microsoft пароли приложений могут не работать) |
| iCloud | `smtp.mail.me.com:587` | STARTTLS | пресет |
| Яндекс | `smtp.yandex.ru:465` | SSL | пресет |
| Mail.ru | `smtp.mail.ru:465` | SSL | пресет |
| Другой | вручную | вручную (`ssl`/`starttls`/`none`) | по умолчанию в форме 465 / SSL |

- **Отображение на nodemailer** (`buildTransportOptions`): `secure = (ssl)`, `requireTLS = (starttls)`, `ignoreTLS = (none)`. Таймауты `connectionTimeout`, `greetingTimeout`, `socketTimeout` = 20 000 мс (`MAIL_TIMEOUT_MS`). Логин = адрес без пробелов по краям; пароль для Gmail очищается от всех пробелов (Google показывает его группами), для остальных только обрезаются края. Тесты проверяют это на поддельном транспорте, реальный сервер в тестах не участвует.
- **Пресеты против «Другого»** (`resolveSmtp`): для пяти сервисов сервер, порт и режим берутся только из пресета, а значения из настроек игнорируются (в тесте подставлены `evil.example:25`/`none`, итог всё равно пресет). У «Другого» пресета нет, поэтому сервер, порт и шифрование задаются вручную (поля видны только для него). Перед соединением код проверяет: сервер не пуст, порт — целое 1–65535, режим — один из трёх. Ещё раньше `sendMail` проверяет, что заполнены адрес, пароль и хотя бы один получатель. При ошибке выдаётся `MailUserError` с понятным текстом, соединение не открывается. Соответствие порта режиму (465↔SSL, 587↔STARTTLS) код **не проверяет**: неверная пара выясняется только при отправке.
- **Режим «Без шифрования» (`none`)** разрешён только для «Другого» (у пресетов такого режима нет): он есть в списке формы и проходит проверку `validate.ts`. При `ignoreTLS` соединение не шифруется даже тогда, когда сервер умеет STARTTLS, так что логин, пароль приложения и письмо идут по сети открытым текстом. **Предупреждения об этом в коде и интерфейсе нет**: в списке просто стоит пункт «Без шифрования». Допустим он разве что для сервера в доверенной локальной сети.
- **Ошибки соединения** (`classifyMailError` → `translateMailError`): `ETLS`, `EREQUIRETLS`, `ECONNECTION` и тексты вроде `wrong version number`/`certificate`/`handshake` относятся к виду `tls`. В комментарии к `ECONNECTION` сказано: «сервер оборвал соединение сразу: обычно не тот порт или шифрование». Для «Другого» пользователь видит: «Проверьте порт и шифрование… обычно порт 465 — SSL, порт 587 — STARTTLS». Для пресетов текст другой: «Проверьте подключение к интернету (иногда мешают VPN или антивирус)». Ошибки вида `tls` не повторяются автоматически, повторяются только `dns`/`network`/`unknown`. `ETIMEDOUT`/`ECONNREFUSED`/`ESOCKET` и т. п. считаются `network` (повтор есть); для «Другого» к тексту добавляется «проверьте адрес сервера и порт».
- Пользователь видит только заранее написанные русские фразы: исходный текст ошибки, коды и пароль в сообщение не попадают (тест NFR-18 проверяет это для всех шести сервисов).

Выводы:
- Абсолютный путь в правиле пишется с **двумя косыми**: `Read(//Users/x/dir/**)`. С одной косой (`Read(/Users/x/…)`) правило не срабатывает: это путь от корня проекта.
- Разрешающие правила **не ограничивают** чтение внутри cwd: всё, что внутри cwd, читается и без них (запуск 1, KZ). Запретить чтение внутри cwd можно только deny-правилом, но deny сильнее allow, и вырезать «всё, кроме папки страны» им нельзя.
- **Решение (запасной вариант из задачи, теперь основной):** cwd процесса = папка страны (или акта/этапа), `StageInvocation.cwd`. Чтение вне cwd в `dontAsk` отклоняется (`permission_denials`, без зависания). В `--allowedTools` явно перечисляются `Read(//<папка страны>/**)` и `Read(//<input.json>)`, если input лежит вне папки.
- Проектные скиллы при cwd во вложенной папке находятся: CLI ищет `.claude/skills` вверх от cwd. Проверено по `init.skills`.
- `--tools` принимает и `Read,WebFetch,WebSearch` одним значением, и отдельными аргументами (проверено по `init.tools`). Используем одно значение через запятую.
- `--tools` и `--allowedTools` вариадические, поэтому промпт ставится сразу после `-p`, а `--allowedTools` — последним флагом.
- Пути в правилах — это реальные пути (на macOS `/tmp` → `/private/tmp`). Оркестратор должен передавать `realpath` папки страны.
- **Отклонение от docs/02 §6:** у SRC-DISCOVER в таблице нет Read, но скилл получает вход файлом `input.json`. Выдаём `Read`, ограниченный cwd (папка этапа) и input. docs/02 §6 исправлен.
- Форма `rate_limit_event`: `rate_limit_info.status` (`allowed`…), `resetsAt`, `rateLimitType`, `unifiedWindows.{five_hour,seven_day}.{utilization,resetsAt,status}`. **Ловушка:** поле `overageStatus: "rejected"` бывает и при обычной работе (докупка выключена организацией), поэтому лимитом считается только `status` вне `allowed*` (у самого события или у окна).

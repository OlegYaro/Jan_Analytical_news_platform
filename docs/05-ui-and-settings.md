# 05. Интерфейс и настройки

Пользователь — не программист. Правила для каждого экрана:
- только русский, простые слова, без терминов «JSON», «SMTP», «CLI», «токен», «селектор»
  (вместо них: «почтовый сервер», «Claude Code», «расход», «способ чтения сайта»);
- у каждого поля — подсказка (иконка «?» или серый текст под полем) и пример;
- ошибки: что случилось + что сделать, без стектрейсов;
- опасные действия (удалить страну) — с подтверждением;
- всё сохраняется автоматически, кнопки «Сохранить» нет; сверху короткое «Сохранено ✓».

## 1. Структура окна

Левое меню: **Главная · Страны · История · Настройки**. Значок в строке меню macOS с пунктами
«Проверить сейчас», «Открыть RegWatch», «Выйти».

## 2. Мастер первого запуска (INS-04)

1. **Проверка компьютера** — результаты `doctor`: Node ✅, Claude Code найден ✅, вход выполнен ✅,
   нужные возможности Claude Code ✅. Если ❌ — что сделать, по шагам, кнопка «Проверить снова».
2. **Папка для отчётов** — по умолчанию `~/RegWatch`, кнопка «Выбрать другую».
3. **Почта** — сервис, адрес, пароль приложения (со ссылкой-инструкцией), получатели, «Отправить
   тестовое письмо». Шаг нельзя пропустить: «Дальше» доступно только после успешного тестового письма. Подсказка: «Без настроенной почты регулярная проверка не запустится».
4. **Что искать** — тема (с готовым текстом по умолчанию), «для кого оценивать».
5. **Страны** — список стартовых стран с переключателями.
6. **Расписание** — список расписаний (до 9): дни, время и страны у каждого; «Запускать при входе в систему».
7. **Проверка источников** — кнопка «Проверить все источники» (можно пропустить) → итог.
8. Готово: «Следующая проверка: понедельник, 08:00». Кнопка «Сделать пробную проверку сейчас».

## 3. Главная

- Статус: «Следующая проверка: пн 23 ноября, 08:00» / «Идёт проверка: Казахстан, анализ 2 из 3» /
  «Пауза до 14:20 — ждём восстановления лимита Claude».
- Кнопки: «Проверить сейчас», «Пробная проверка (без письма)», «Проверить за период…».
- Последний прогон: дата, «Проверено 9 из 9», найдено N, письмо отправлено/не нужно/ошибка.
- Если почта не настроена/не проверена: заметный баннер «Без настроенной почты регулярная проверка не запустится» со ссылкой в Настройки → Почта; кнопки запуска (кроме пробной) и расписание заблокированы.
- Предупреждения: источники с ❌, страны со сбоями, неотправленные письма.

## 4. Страны (CTY)

Таблица: `[✓ Участвует] | 🇺🇿 Узбекистан | Источников: 4 | Источники ✅ | Проверено 23.11 | Изменений нет`.
Кнопки над таблицей: «Добавить страну», «Проверить все источники».

Карточка страны (по клику, справа или отдельной страницей):
- **Источники** — список: название, адрес (кликабельный), тип, язык, основной/дополнительный,
  переключатель «Включён», состояние ✅/⚠/❌ с пояснением, дата проверки, «Что видно на сайте»
  (5 последних документов из пробного извлечения). Кнопки: «Добавить источник», «Изменить»,
  «Удалить», «Проверить этот источник», «Проверить все источники страны»,
  «Найти недостающие источники» (если какого-то типа нет), «Найти основные законы» (SRC-09: предлагает отслеживаемые акты по типам из `08`; добавляются только после нажатия «Добавить»).
- **Органы и уровень отбора** (CTY-09) — таблица: орган (название как в источнике), класс **1 / 2 / 3** (выпадающий список). Подсказка: «1 — финансовые регуляторы: их акты проходят отбор всегда. 2 — общие законодатели (закон, президент, правительство): акт берётся, если в тексте есть банковские нормы. 3 — прочие органы: берётся, только если в тексте есть банковские слова. Если список не заполнен, все органы считаются классом 2 — это дороже, но ничего не теряется». Кнопки: «Добавить орган», «Вернуть стандартные». Органы, замеченные при сборе и ещё не внесённые в список, показываются как «Новые» с классом 2.
- **Отслеживаемые акты** — название, номер регистрации, ссылка, состояние; «Добавить акт».
- **Последние находки** по стране со ссылкой в «Историю».

Форма «Добавить источник»: адрес; тип (выпадающий список с пояснениями: «Правовая база — официальный
сайт законодательства», «Регулятор — центральный банк или надзорный орган», «Проекты актов —
портал обсуждения проектов», «Новости — только подсказки, не основной источник»); язык; основной
или дополнительный. После сохранения — автоматически предлагается «Проверить источник».

## 5. История (ARC-03)

Список прогонов: дата, режим, «Проверено N из N», найдено, письмо. Внутри: страны → отчёт (RU/EN
переключатель), «Как проверяли» (верификация по полям), «Что отброшено и почему», лог простыми
словами, «Открыть папку в Finder». У каждой находки: «Ложное срабатывание», у прогона — «Был пропущен
акт…» (форма: ссылка + комментарий) → в эталоны (HAL-07).

Как устроено (бэкенд `src/main/history.ts`, `golden-cases.ts`; мост `window.rw.history`, тип `HistoryApi`):
- **Список** — новые сверху; «Проверено N из N» = страны с итогом «есть изменения»/«изменений нет» из всех стран
  прогона; «Найдено» = существенных / для сведения / не удалось проверить (сумма `result.json` стран); письмо — из
  очереди `state/outbox.json` (иначе `run.json`); прогон с битым `run.json` в списке не показывается.
- **Страна** — находки (существенные, для сведения, ⚠ не удалось проверить; у существенных — «⚠ не подтверждено»
  и спорные поля); «Что отброшено и почему»: отбор по названию, экран по тексту (модель или код), журнал
  отправленного и дубли (код); «Как проверяли»: вердикт и статус каждого поля по последнему проходу проверки;
  отчёт RU/EN (нет файла — «отчёта нет»); журнал — сводные строки (сбор, отбор, решения экрана, карточки,
  проверка, итог, пауза), последние 200; расход страны.
- **«Открыть папку в Finder»** — папка прогона или страны (открывается сама папка). Путь проверяется: только
  внутри рабочей папки.
- **«Ложное срабатывание»** у находки и **«Был пропущен акт…»** у страны прогона (ссылка `https://…` +
  комментарий до 1000 знаков) сохраняют случай в `golden/cases/` рабочей папки (`04` §11). Повторное нажатие
  второго случая не создаёт; помеченная находка показывается помеченной.

## 8. Формат письма (DLV-02)

Письмо собирает код из карточек (`headline`, `top_changes`, `act`, `change_count`, `links`) и `screen.json`; модель только переводит (если выбран русский). Подробный отчёт — в архиве (`runs/<id>/<страна>/report.md`) и в экране «История»; в письме ссылка «Подробно в приложении». Страны без находок не расписываются.

Образец на эталоне 24/2:

```
🇺🇿 Узбекистан — 2 существенных, 3 для сведения, 1 не удалось проверить
Корпоративное управление в банках
Пост. Правления ЦБ № 24/2 от 17.09.2026, рег. МЮ № 3254-2 от 09.10.2026
Вступает 13.01.2027, переходного периода нет
Изменяет Положение рег. № 3254. Изменений: 10 — 🔴 3 · 🟠 4 · ⚪ 3
🔴 п. 8 — … (внедрить сложно)         ← не больше 3 строк 🔴 (top_changes)
Читать: изменения · действующая редакция · новая редакция
Для сведения
· Платёжный коммутатор ЦБ — пост. № 22/4, вступает 25.01.2027 — ссылка
⚠ Не удалось проверить
· … — причина — ссылка
Проверено 9 из 9 стран · Не является юридической консультацией · Подробно в приложении
```

Правила:
- Строка-сводка: число существенных (`material` с карточкой), «для сведения» (`minor`), «не удалось проверить» (SCR-04, `⚠ не подтверждено`). Нулевые части не пишутся.
- «Читать:» — три ссылки из `links`: изменяющий акт, текущая редакция, редакция на дату вступления.
- 🔴 = значимое, 🟠 = менее значимое, ⚪ = незначимое (счётчик по `changes[]`); строки 🔴 — из `top_changes` (≤ 3), остальное в приложении.
- «Для сведения»: одна строка на акт — название, номер, дата вступления (если есть), ссылка.
- «⚠ Не удалось проверить»: название, причина простыми словами (нет текста, ошибка модели, не подтверждено), ссылка. Такие акты не пропадают из письма.
- Подвал: «Проверено N из N стран» и страны со сбоем, «Не является юридической консультацией».
- HTML + текстовая версия (DLV-04); читается на телефоне.
